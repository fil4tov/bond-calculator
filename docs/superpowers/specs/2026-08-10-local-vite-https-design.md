# Локальный HTTPS для Vite

## Контекст

Frontend запускается из `frontend/` командой `pnpm dev`. Сейчас Vite слушает HTTP,
а `/api` проксируется в локальный FastAPI по HTTP. HTTPS нужен только для обычной
локальной разработки. Production-сборка, `vite preview` и E2E должны сохранить
текущий протокол.

## Решение

- Добавить `vite-plugin-mkcert` в `devDependencies` frontend-пакета.
- Подключить `mkcert()` в `frontend/vite.config.ts` только для обычного режима
  разработки.
- Запускать Playwright dev-сервер в отдельном режиме `e2e`, в котором плагин не
  активируется. Его текущие HTTP URL и настройки браузера не меняются.
- Не менять HTTP target Vite-прокси: TLS завершается на Vite, а связь Vite с локальным
  backend остаётся внутренней и продолжает работать по HTTP.
- Обновить README: адрес frontend становится `https://127.0.0.1:5173`; первый запуск
  может потребовать установки локального доверенного центра сертификации mkcert.

## Поведение

После установки зависимостей `pnpm --dir frontend dev` открывает frontend по HTTPS.
Сертификат создаётся и обслуживается `vite-plugin-mkcert`; сертификаты и ключи не
добавляются в репозиторий.

Команды `pnpm --dir frontend build`, `pnpm --dir frontend preview` и
`pnpm --dir frontend test:e2e` сохраняют прежнее поведение. E2E продолжает обращаться
к `http://127.0.0.1:4173`.

## Ошибки и ограничения

На первом запуске plugin может запросить разрешение операционной системы на установку
локального CA. Если mkcert не сможет создать или установить сертификат, Vite завершит
запуск с его диагностикой; автоматический переход обратно на HTTP не выполняется,
поскольку он скрывал бы нарушение требуемого режима.

## Проверка

Изменение относится к конфигурации, поэтому отдельный unit-тест не добавляется.
Проверка включает:

- загрузку Vite-конфигурации и фактический старт обычного dev-сервера по HTTPS;
- подтверждение, что E2E-режим остаётся HTTP;
- `pnpm --dir frontend typecheck`;
- `pnpm --dir frontend build`.
